## A. Decisions (ruled; cite, don't re-litigate)

**D1 — The seam: no new verb, one service, three phases.** `perform_agent_create` is the placement authority; `harness agent create` and `runtime.agent.create` are its two doors and stay byte-parallel; `persona instance create --add-instance` stays the roster-only recovery door and is not touched. The service gains a pure `layout` step before any write (D2) and a `skills` phase after `placement` (D5). **Why:** UC-H1/H3 already hoisted the sequence out of the RPC handler precisely so a lane switch is never a behaviour change; a second verb (`agent place`) would be the parallel authority the master prompt forbids. **The authority question, answered as two questions:** the persona-instance row answers "does this agent exist" (the roster-only door legitimately mints rows with no placement); the instance-keyed office actor answers "is it on this level"; the reservation receipt is the join for one gesture. "Placed" ≡ a live actor whose `persona_instance_id` names a live row. A row without an actor is `unplaced` (legal); an actor whose instance is retired or missing is an `orphan_actor` (defect). Neither store is folded into the other; the join gets a read-only census (`harness doctor` → `placement_census`, D8) rather than a merge.

**D2 — Auto-layout: hermes owns the policy; the launcher keeps a fixture-pinned prediction.** New pure module `agent_runtime/office_layout_policy.py` — `next_free_slot(occupied: Iterable[tuple[float,float]], *, lane_offset=(0,0)) -> tuple[float,float]` and `occupied_positions(actors, *, folder)` — with the SAME constants and scan order as the launcher's `MissionOfficePlacementPolicy` (F10), and one shared case fixture committed byte-identical in both repos (`tests/fixtures/office_layout/cases.json` ↔ launcher `test/fixtures/harness_office_layout/cases.json`, `MANIFEST.sha256` on both sides, the `harness_stream` pattern). `position` becomes OPTIONAL on `runtime.agent.create` and `--pos` optional on `agent create`: present → operator data, verbatim, exactly as today; absent → the policy over the workspace's live actors in the request's folder. The ack gains `position: [x, y]` and `actor: <the row as stored>` — additive on an existing ack, no manifest integer move; the launcher adopts the SERVER's actor (this is what discharges [office-gesture-prediction-remainder](office-gesture-prediction-remainder.md) Row 2's "adoption trusts the client's key"). **Why hermes:** two policies that can disagree are the defect this plan exists for; a policy on the server is the one every door shares, and a fixture pin is how this codebase already keeps two repos byte-equal. **Why the launcher keeps a copy:** the pending chip and the staged node need a world position before the ack, and the prediction is cheap to pin.

**D3 — Notification: no surface-revision bump; the existing `office_actor` create patch is the frame; S0 proves it live.** Ruled against bumping `surface.revision` on actor writes (F5). The frame a client consumes is the `patch` batch carrying `{entity: office_actor, op: upsert, created: true}` and `{entity: persona_instance, op: upsert, created: true}` from one create; the consumer is `MissionReadModel._applyOfficeActorPatch` + the generic `persona_instance` fold. A client that declares no folds receives the demoted full core (correct, costlier); a client not connected hydrates on reconnect. Both degrade to "stale until refresh", never to a wrong render, because the scene is derived from snapshot truth, not from a revision counter. **What the plan adds:** the live proof and a byte-pinned golden of the two-patch batch in both fixture dirs (S0). If S0 shows a demote or a drop, its reason is the first slice's finding and everything downstream waits on it.

**D4 — Idempotence and failure: keep the reservation; add a resumable `skills` phase; never roll back a placed agent for a skill fault.** Reservation states become `instance_minted → placed → done | rolled_back` (`placed` is today's `done`; the rename keeps the receipt honest about which phase the key resumes at). A `skills`-phase refusal returns `phase: "skills"`, `rolled_back: false`, `resume: "retry with the SAME idempotency_key"`, and the receipt retains the requested skill list; a retry with the same key re-enters at `skills` without re-minting or re-placing. **Why:** a placed agent without its skills is exactly what every launcher drop is today — a valid, messageable state; retiring it to satisfy atomicity would archive a working agent to undo a file copy. Placement-phase compensation stays as it is (retire = archive). The unstamped `AgentCreateInvalid` arms (F3) get `rolled_back: True` in the same slice.

**D5 — Skills: the verb assigns AND installs, at the instance tier, behind two new gates.** `--skill <id>` (repeatable) writes `skill_overrides` on the NEW instance through `PersonaInstanceStore.update_profile(skills=[…])` — never `persona.skills` (a persona-tier write would silently reconfigure every other instance of that persona, and no operator verb has ever done that). Absent `--skill` leaves `skill_overrides = None` (inherit). Before assignment: (a) every id must resolve `status == "resolved"` under `agent/skill_utils.resolve_skills` or the phase refuses `skill_unresolved` naming the id and its status (`missing | collision | invalid_source`); (b) every CANONICAL id (`CANONICAL_SHARED_SKILL_IDS`) is passed through `install_harness_skill` first, and after install `harness_skill_hash_mismatches([...])` must be empty or the phase refuses `skill_install_diverged` with both hashes. That is the gate the repo→installed join has never had (F14): the verb refuses to hand an agent a stale copy, instead of reporting it at severity 15. **Also in this slice:** the `None → []` collapse in `_cmd_persona_instance_update_profile` is fixed (omitted `--skill` → `None`), with a red-first test. **Why not split:** the 2026-08-24 incident was a running agent reading a 14457-byte copy of a 14906-byte skill; a verb that leaves the copy stale reproduces that on every fresh machine and calls itself done.

**D6 — Desk rule: the verb authors no desk; the store refuses a second authored desk per persona.** `agent create` continues to write one `kind: "agent"` item and nothing else — that is parity with the launcher's drop (F9), and the operator's 2026-08-20 ruling that desks are separate things. A second instance of a persona shares that persona's desk by construction (desks are persona-keyed on the launcher; the implicit desk renders under an instance whose persona has no authored desk). The one-per-persona rule moves into the store as defence in depth: `OfficeStore.upsert_actor` refuses a payload that adds a `kind: "desk"` item for a persona that already holds a live desk item anywhere in the workspace — typed `DuplicateDeskRefused`, RPC `ERR_CONFLICT` with `data.reason = "duplicate_desk"` naming the holding `actor_key` and `item_id`, CLI exit code alongside `duplicate_conflict`; a move of the SAME desk item is not a duplicate. Realm pull (`office_sync.apply_office_pull`) writes files directly and is deliberately outside this guard — a pulled duplicate is a conflict-lane fact, not a local write. The launcher's `hasAuthoredDeskForPersona` stays as the client-side guard; the render-time `duplicate_desk` warning stays as the detector for data that predates the fence. **Owner decision with a default:** refuse (recommended — the store already refuses class-key collisions in exactly this shape) vs. warn-and-write. Nothing blocks on it; S3 ships the refusal unless the owner says warn.

**D7 — The inverse is one verb, RPC-first, over the store method that already does it.** New `agent_runtime/agent_retire.py::perform_agent_retire(params)` wrapping `PersonaInstanceStore.retire` (which already archives the row AND the actors, F16) with a typed ack `{persona_instance_id, archive_path, archived_actor_keys: [...], office_archive_failures: [...]}` — the `office_archive_failures` list makes the today-swallowed best-effort office half VISIBLE (empty means every bound actor archived). Two doors: `runtime.agent.retire` (`serve_rpc.py`, `@method`) and `hermes harness agent retire <persona_instance_id> [--reason] [--json]`. `persona instance retire` stays and calls the same function. Archive trail unchanged: row archive + actor archive + `persona_instance.retired` + `office.actor.removed` (+ their patches). **Launcher:** `_removePersonaFromScene` for a deliberate placement calls `runtime.agent.retire` and stops sending `runtime.office.remove` for that actor; `persona.instance.retire` argv survives on exactly the `Unavailable` arm (the office write-lane rule: a refusal is terminal, only Unavailable falls back). `runtime.office.remove` remains the verb for items retire cannot reach (class-keyed actors, authored desks). **Why:** the two-lane removal is the roster-vs-office two-authority problem in its delete form; the join already exists inside `retire`, it just has no door and no ack.

**D8 — Flags and the census.** Every verb that takes a workspace accepts BOTH `--workspace` and `--workspace-id` (argparse option-string aliases on the existing dest; nothing removed, nothing renamed); a parser-walk test pins that every subcommand exposing either spelling exposes both. The launcher's committed argparse dump (`tool/hermes_cli_contract/dump_hermes_cli_contract.dart`, gate `test/features/mission_control/harness_capability_argv_test.dart`) is refreshed in the same landing. `harness doctor` gains `placement_census`: per workspace, `placed` / `unplaced_rows` / `orphan_actors` with ids, `health` unknown-not-ok when either store is unreadable — read-only, no repair (repair is `agent retire` or `agent create` with the resumed key).

**D9 — Name and the "for `<task>`" half.** The verb keeps its name. The operator's task is not a field: the goal/task lane was removed 2026-07-30 and the first message IS the task (`tests/hermes_cli/test_created_agent_first_message.py` pins the created agent's first-message path). `--display-name` carries the roster name; a `--first-message` on `agent create` is listed under §E as deliberately left out, with the reason.

## D. Risks

- **S0 may fail, and that is its job.** If a second-process create demotes (a not-coverable event in the same batch — e.g. `persona_instance.chat_opened` arriving beside the patches) or the fold refuses, the remedy is in `patch_coverage` or the read model, not in this verb; the plan halts at S0 with the reason recorded, and no slice builds on a lane that was assumed.
- **Two policies, one fixture.** The fixture pin proves equality on the cases in the file, not on every floor. A launcher-only behaviour (hidden items count as occupied; `_layoutOverride` included in the scanned layout) must be represented in the fixture or it silently diverges. The case list in S1 is the minimum; add a case for every constant.
- **The desk fence meets pulled data.** A workspace pulled from a realm can already hold two desks for one persona; the fence refuses the NEXT write, not the existing state. The render-time `duplicate_desk` warning stays for exactly that, and `harness office actor-upsert` on such a workspace will refuse a desk move until one is archived — a refusal with the holder named, not a silent write.
- **The skills gate makes `agent create` slower on a cold machine** (a `copytree` per canonical skill on first placement). It is bounded (the canonical set) and idempotent (hash-equal → no copy); the drop timeline's `phases` gains `skills_ms` so it is billed, not hidden.
- **`STATE_PLACED` changes a receipt vocabulary.** Existing `done` receipts must read as `done`; a resumed old receipt must not re-enter `skills`. The reservation loader treats an unknown state as `reservation_corrupt` today — the migration is one alias, but it is a migration.
- **The launcher's argv fallback for retire is a different verb from the RPC.** `persona.instance.retire` argv returns no `archived_actor_keys`; on the `Unavailable` arm the intent resolves by the next read, as removals do today. Named, not hidden.
- **Persona home outside `<root>/profiles/`** (F15 inference). S4's gate hashes the RESOLVED shared root; if a binding splits the root the mismatch surfaces as `skill_install_diverged`, which is the honest answer, but the operator will need the doctor's `persona_binding` row to see why.

## E. Left out, deliberately

- **A `--first-message` / `--task` on `agent create`.** The task is the first chat message and `mission chat message` is its verb; folding a turn into a create would put a provider call inside a store transaction. If it is wanted it is its own capability id, after this plan.
- **A persona-template (`persona.skills`) verb.** No operator verb has ever written it; the instance tier is the lane. Recorded as owner decision D10(ii).
- **Bumping the office surface `revision` on actor writes.** Ruled out in D3 with its reason; do not re-propose as "so clients notice" — clients notice through the fold.
- **A hermes-side `duplicate_desk` render warning.** hermes has no render; the store fence is the hermes half, the launcher warning the other.
- **Deleting `persona instance create --add-instance`.** It is the serve-absent recovery door and mints no placement on purpose; its docstring already says so. A future `harness doctor` row could flag rows it mints that never get placed — that is `placement_census`'s `unplaced_rows`, already in D8.
- **The argv capability arms under the office RPC verbs** — owned by [office-write-lane-collapse](office-write-lane-collapse.md) Row 1; nothing here touches their deletion criterion.
- **Whole-section `offices` fold entity.** The office is reached by `office_actor` + `office_surface`; a section fold would re-send every actor for one write.
- **Realm-pull events for `WRITE_REMOTE`** (`apply_office_pull` writes files with no office event) — a real gap in the notification story, but a realm-sync one; filed against 06's open rows, not this verb.
